# JDU Web Infrastructure

[日本語](README.md) · **Русский** · [O‘zbekcha](README.uz.md)

Учебные материалы JDU по развёртыванию веб-инфраструктуры. В этом семестре они используются во второй половине курса `Introduction-CyberSecurity`. В дальнейшем на их основе можно будет проводить отдельный курс.

Студенты настраивают DNS, веб-сервер и базу данных на экземплярах EC2 внутри VPC и подключают приложение, предоставленное преподавателем, к веб-серверу и базе. Они изучают сетевые маршруты, доступ к сервисам, порты, журналы, сохранение данных и восстановление. Программировать приложение в рамках курса не требуется.

## Развёртывание учебной среды в AWS

### Новый пробный порядок работы с одним запуском для каждой роли

Запустите свой Learner Lab в AWS Academy и вставьте команды ниже в CloudShell региона Северная Вирджиния (`us-east-1`). В начале выберите English, 日本語, Русский или O‘zbekcha. На выбранном языке отображаются подсказки ввода, ход настройки, результаты и сообщения об ошибках.

```bash
setup=$(mktemp)
curl -q -fsS https://raw.githubusercontent.com/ShinyaHaga0910/JDU-Web-Infrastructure/main/development/setup-classroom.sh -o "$setup" &&
  bash "$setup" teacher
```

При новом развёртывании используется текущая версия GitHub. При возобновлении настройки студента необходимые файлы загружаются из версии, с которой началась настройка.

1. **Преподаватель** запускает команды в своём Learner Lab с аргументом `teacher`. Скрипт определяет аккаунт преподавателя по сеансу CloudShell. Введите через пробел только номера аккаунтов AWS студентов. Передайте содержимое каждого файла `*.invitation.txt` лично соответствующему студенту.
2. **Студент** запускает команды в своём Learner Lab, заменив `teacher` на `student` в последней строке. Введите личный код приглашения и задайте пароль RDP для сервера доступа. Введённые значения скрыты. CloudFormation создаёт пять экземпляров EC2. Скрипт размещает учебные файлы, проверяет внутреннее SSH-подключение и с сервера доступа регистрирует среду и отправляет пробный результат в API преподавателя.

Скрипт сверяет версии и SHA-256 пакетов по данным GitHub и передаёт их на сервер пакетов через CloudShell и AWS Systems Manager. Создавать S3 для учебных материалов и вводить Class ID не нужно.

Новый стек преподавателя называется `jdu-web-infrastructure-teacher`, стек студента — `jdu-web-infrastructure-student-<Lab ID>`.

Полная проверка нового порядка в Learner Lab ещё не завершена. Вход через учебный аккаунт Google и проверка заданий через Web Portal настраиваются отдельно.

## Прежний порядок выдачи материалов через S3

### Для преподавателя

В AWS Academy запустите **Learner Lab преподавателя** для нужного класса и выполните команды в CloudShell региона Северная Вирджиния (`us-east-1`).

```bash
url='https://raw.githubusercontent.com/ShinyaHaga0910/JDU-Web-Infrastructure/8b080f940957fe3898e65d5a31978f581aa86dd0/development/01_roles/cyber_security/tools/web_lab_teacher/install_teacher.py'
script=$(mktemp) &&
  curl -fsS "$url" -o "$script" &&
  printf '%s  %s\n' 'f943d815e52f38442e292ffd5f74a15b4327c00618a2b8afa3a0d97ee384a2a6' "$script" |
    sha256sum -c - &&
  python3 -B "$script"
```

Скрипт определяет аккаунт AWS по текущей сессии CloudShell и через CloudFormation создаёт VPC, экземпляр EC2, фиксированный IPv4-адрес, API проверки заданий, таблицу DynamoDB и закрытое хранилище S3 для преподавателя. Вводить Class ID и номер аккаунта AWS не нужно. После развёртывания скрипт проверяет HTTPS-доступ к API и настройки хранилищ. Для предварительной проверки без создания ресурсов добавьте `--plan` к последней строке.

Перед началом работы со студентами загрузите учебные материалы, подготовьте подписанный пакет для нового API проверки и настройте страницу заданий со входом через учебный аккаунт Google. [Подробнее о скрипте преподавателя (на японском)](development/01_roles/cyber_security/tools/web_lab_teacher/README.md) · [Первичная выдача материалов и регистрация (на японском)](course/labs/INITIAL-WORKFLOW.md)

### Для студента

Запустите свой **Learner Lab студента** и откройте CloudShell в том же регионе. Проверьте подпись и срок действия общего пакета, указанного преподавателем, и получите свой зашифрованный пакет. Затем следуйте инструкции по первичному развёртыванию, чтобы создать в CloudFormation пять экземпляров EC2 и зарегистрировать среду для проверки заданий. [Первичное развёртывание (на японском)](course/labs/INITIAL-WORKFLOW.md) · [Общая подготовка P0](course/labs/docs/ru/p0.md)

## Практические упражнения P и самостоятельные задания M

13 ноября 2026 года [материалы упражнений и заданий](course/labs/README.md) были распределены по отдельным страницам без P3/M3. На японском, русском и узбекском языках доступны 44 шага с примерами и критерии оценивания на 59 баллов. После первоначальной настройки [проверяйте задания и смотрите результаты на веб-портале](course/labs/docs/ru/portal.md). PDF формата A4 и HTML для просмотра без подключения к интернету входят в ZIP-архив материалов.

В версии r1.1 были добавлены пояснения к командам и настройкам всех 49 шагов прежней редакции, описание принципов каждого упражнения P, вопросы для самопроверки и примеры чтения сетевых маршрутов и вывода команд. В заданиях M предусмотрены указания по самостоятельному планированию действий и способов проверки.

Подписанный пакет r3 действителен до конца 31 января 2027 года по времени Узбекистана (UZT). 3 ноября проверили создание пяти новых экземпляров через CloudFormation, первичную регистрацию, размещение материалов, привязку Google и AWS, настройку P1/M1 через SSM, проверку в браузере, сохранение оценок и их отображение преподавателю. [Порядок действий и команды для первого запуска](course/labs/INITIAL-WORKFLOW.md). **Студенты ещё не прошли все 44 шага в рамках проверки. Вычитка носителями языка и визуальная проверка преподавателем также не проведены.** В [отчёте о проверке](course/labs/VALIDATION.md) указан объём выполненных проверок. Для курса в целом `CLASS_READY` остаётся `false`.
