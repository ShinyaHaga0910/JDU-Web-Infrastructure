# JDU Web Infrastructure

[日本語](README.md) · **Русский** · [O‘zbekcha](README.uz.md)

Учебные материалы JDU по развёртыванию веб-инфраструктуры. В этом семестре они используются во второй половине курса `Introduction-CyberSecurity`. В дальнейшем на их основе можно будет проводить отдельный курс.

Студенты настраивают DNS, веб-сервер и базу данных на экземплярах EC2 внутри VPC и подключают приложение, предоставленное преподавателем, к веб-серверу и базе. Они изучают сетевые маршруты, доступ к сервисам, порты, журналы, сохранение данных и восстановление. Программировать приложение в рамках курса не требуется.

## Развёртывание учебной среды в AWS

### Новый пробный порядок работы с одним запуском для каждой роли

Запустите свой Learner Lab в AWS Academy и вставьте команды ниже в CloudShell региона Северная Вирджиния (`us-east-1`). В начале выберите English, Japanese, Русский или O‘zbekcha. На выбранном языке отображаются подсказки ввода, ход настройки, результаты и сообщения об ошибках.

#### Команда для преподавателя

```bash
setup=$(mktemp)
curl -q -fsS https://raw.githubusercontent.com/ShinyaHaga0910/JDU-Web-Infrastructure/refs/heads/main/development/setup-classroom.sh -o "$setup" &&
  bash "$setup" teacher
```

При новом развёртывании используется текущая версия GitHub. При возобновлении настройки студента необходимые файлы загружаются из версии, с которой началась настройка.

**Преподаватель** запускает команды в своём Learner Lab с аргументом `teacher`. После выбора языка настройка и проверка выполняются автоматически. Передайте общий код, который появится в конце настройки, только участникам курса.

#### Команда для студента

Вставьте следующие команды в CloudShell (`us-east-1`) своего студенческого Learner Lab.

```bash
setup=$(mktemp)
curl -q -fsS https://raw.githubusercontent.com/ShinyaHaga0910/JDU-Web-Infrastructure/refs/heads/main/development/setup-classroom.sh -o "$setup" &&
  bash "$setup" student
```

Выберите язык, вставьте общий код регистрации, полученный от преподавателя, и придумайте свой пароль длиной от 4 до 128 символов для подключения к рабочему столу учебного сервера доступа. Вставленный код регистрации виден на экране. Введите пароль дважды для подтверждения. В обоих случаях каждый введённый символ отображается как `*`. Запомните пароль: без него вы не сможете подключиться к серверу и продолжить практикум. Скрипт создаёт отдельный идентификатор Lab и токен для проверки заданий, а CloudFormation создаёт пять экземпляров EC2. После размещения файлов для настройки серверов и проверки внутреннего SSH-подключения скрипт отправляет пробный результат с сервера доступа в API преподавателя.

Скрипт загружает до восьми пакетов одновременно из официальных источников и сверяет их с версиями и SHA-256, указанными в GitHub. CloudShell объединяет файлы в несколько архивов и передаёт до пяти архивов одновременно на сервер пакетов через AWS Systems Manager. После распаковки сервер ещё раз проверяет каждый файл. Прогресс загрузки файлов и передачи архивов обновляется каждые 30 секунд. Создавать бакет S3 для файлов настройки серверов и вводить Class ID не нужно.

После разрыва соединения снова запустите студенческую команду в том же CloudShell. Скрипт сверит SHA-256 файлов в домашнем каталоге и повторно использует файлы с совпадающими хешами. После успешной тестовой отправки в систему оценивания скрипт удалит эти временные копии.

После настройки внутреннего репозитория скрипт одновременно настраивает и проверяет пять серверов. При подготовке внутреннего SSH скрипт параллельно получает ключи четырёх серверов, затем параллельно регистрирует на них ключ сервера доступа. Файлы для настройки серверов размещаются на веб-сервере и сервере базы данных одновременно.

Новый стек преподавателя называется `jdu-web-infrastructure-teacher`, стек студента — `jdu-web-infrastructure-student-<Lab ID>`.

Полная проверка нового порядка в Learner Lab ещё не завершена. Вход через учебный аккаунт Google и проверка заданий через Web Portal настраиваются отдельно.

#### Если вы забыли пароль RDP

Запустите сервер доступа, созданный по новой инструкции, и вставьте команды ниже в CloudShell (`us-east-1`), где вы настраивали студенческую среду.

```bash
setup=$(mktemp)
curl -q -fsS https://raw.githubusercontent.com/ShinyaHaga0910/JDU-Web-Infrastructure/refs/heads/main/development/setup-classroom.sh -o "$setup" &&
  bash "$setup" reset-rdp
```

Выберите язык. Если скрипт найдёт несколько сред Lab, выберите нужную. Введите новый пароль длиной от 4 до 128 символов дважды. Каждый введённый символ отображается как `*`. Старый пароль и общий код регистрации вводить не нужно. После сброса подключитесь под именем `labuser` с новым паролем.

## Прежний порядок выдачи материалов через S3

### Для преподавателя

В AWS Academy запустите **Learner Lab преподавателя** для нужного класса и выполните команды в CloudShell региона Северная Вирджиния (`us-east-1`).

```bash
url='https://raw.githubusercontent.com/ShinyaHaga0910/JDU-Web-Infrastructure/8b080f940957fe3898e65d5a31978f581aa86dd0/development/01_roles/cyber_security/tools/web_lab_teacher/install_teacher.py'
script=$(mktemp) &&
  curl -fsS "$url" -o "$script" &&
  printf '%s  %s\n' 'f943d815e52f38442e292ffd5f74a15b4327c00618a2b8afa3a0d97ee384a2a6' "$script" |
    sha256sum -c - &&
  python3 -B "$script"
```

Скрипт определяет аккаунт AWS по текущей сессии CloudShell и через CloudFormation создаёт VPC, экземпляр EC2, фиксированный IPv4-адрес, API проверки заданий, таблицу DynamoDB и закрытое хранилище S3 для преподавателя. Вводить Class ID и номер аккаунта AWS не нужно. После развёртывания скрипт проверяет HTTPS-доступ к API и настройки хранилищ. Для предварительной проверки без создания ресурсов добавьте `--plan` к последней строке.

Перед началом работы со студентами загрузите учебные материалы, подготовьте подписанный пакет для нового API проверки и настройте страницу заданий со входом через учебный аккаунт Google. [Подробнее о скрипте преподавателя (на японском)](development/01_roles/cyber_security/tools/web_lab_teacher/README.md) · [Первичная выдача материалов и регистрация (на японском)](course/labs/INITIAL-WORKFLOW.md)

### Для студента

Запустите свой **Learner Lab студента** и откройте CloudShell в том же регионе. Проверьте подпись и срок действия общего пакета, указанного преподавателем, и получите свой зашифрованный пакет. Затем следуйте инструкции по первичному развёртыванию, чтобы создать в CloudFormation пять экземпляров EC2 и зарегистрировать среду для проверки заданий. ## Практические упражнения P и самостоятельные задания M

13 ноября 2026 года [материалы упражнений и заданий](course/labs/README.md) были распределены по отдельным страницам без P3/M3. На японском, русском и узбекском языках доступны 44 шага с примерами и критерии оценивания на 59 баллов. PDF формата A4 и HTML для просмотра без подключения к интернету входят в ZIP-архив материалов.

В версии r1.1 были добавлены пояснения к командам и настройкам всех 49 шагов прежней редакции, описание принципов каждого упражнения P, вопросы для самопроверки и примеры чтения сетевых маршрутов и вывода команд. В заданиях M предусмотрены указания по самостоятельному планированию действий и способов проверки.

Подписанный пакет r3 действителен до конца 31 января 2027 года по времени Узбекистана (UZT). 3 ноября проверили создание пяти новых экземпляров через CloudFormation, первичную регистрацию, размещение материалов, привязку Google и AWS, настройку P1/M1 через SSM, проверку в браузере, сохранение оценок и их отображение преподавателю. [Порядок действий и команды для первого запуска](course/labs/INITIAL-WORKFLOW.md). **Студенты ещё не прошли все 44 шага в рамках проверки. Вычитка носителями языка и визуальная проверка преподавателем также не проведены.** В [отчёте о проверке](course/labs/VALIDATION.md) указан объём выполненных проверок. Для курса в целом `CLASS_READY` остаётся `false`.
