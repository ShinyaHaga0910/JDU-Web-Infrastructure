## Что изучаем

Проверить файл и права на исходном EBS; доказать сохранение после stop/start того же Web.

## Задание

Создайте marker P3 со своим анонимным Lab ID. Зафиксируйте состояние до остановки, stopped и после запуска. Дополнительный диск, mount и backup/restore не требуются.

- File: /var/lib/jdu-web/practice/storage.txt

```text
lab_id={lab_id}
task=P3
payload=practice-storage-2026
```

## Как это работает

**Состояние перед началом:**

Маркер можно сохранить на исходном корневом EBS того же Web.

**Что изменится в этом P:**

Сохранность после stop/start того же Web подтверждена данными до и после.

Различайте оперативную память и сохранённый файл на EBS. Здесь выполняется Stop/Start того же Web с исходным EBS. Сравните хеш, instance/volume ID и изменение boot ID. Автоматический public IPv4 может измениться. [Остановка и запуск EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/Stop_Start.html).

## Пример решения: выполняйте по одному шагу

### P3.1 Проверить исходный диск и свободное место

**Место выполнения:**

SSM-терминал Web-сервера: ssm-user

**Цель и действия:**

findmnt показывает файловую систему, lsblk - диски и разделы, df -h - свободное место. Используйте предоставленный root EBS; имя /dev/nvme не является причиной менять диск.

```bash
findmnt -T /var/lib
lsblk -o NAME,TYPE,SIZE,MOUNTPOINTS,SERIAL
df -h /var/lib
cat /proc/sys/kernel/random/boot_id
```

**Смысл команд и настроек:**

Findmnt показывает файловую систему пути, lsblk - блочные устройства, df - свободное место. Это разные наблюдения. Boot_id идентифицирует текущую загрузку, а хеш - содержимое файла.

**Ожидаемый результат и его смысл:**

Соответствует исходному root volume; свободно не менее 20% и 2 GiB. Сохраните boot_id текущей загрузки.

**Если не получилось:**

Недостаток места - проблема готовности. Не удаляйте другие материалы или диски ради баллов.

### P3.2 Создать и разместить marker

**Место выполнения:**

SSM-терминал Web-сервера: ssm-user

**Цель и действия:**

Задайте LAB_ID и в этом терминале. printf завершает строки переводом строки. install задаёт directory 0755 и файл 0644/root:root. Сначала проверьте существующий файл; не заменяйте отличающееся содержимое без выяснения причины.

```bash
LAB_ID='YOUR-LAB-ID'
cd ~
mkdir -p jdu-web-practice/p3
cd jdu-web-practice/p3
printf 'lab_id=%s\ntask=P3\npayload=practice-storage-2026\n' "$LAB_ID" > storage.txt
cat storage.txt
sudo install -d -o root -g root -m 0755 /var/lib/jdu-web/practice
sudo install -o root -g root -m 0644 storage.txt /var/lib/jdu-web/practice/storage.txt
stat -c '%U:%G %a %n' /var/lib/jdu-web/practice /var/lib/jdu-web/practice/storage.txt
sha256sum /var/lib/jdu-web/practice/storage.txt
```

**Смысл команд и настроек:**

Printf подставляет LAB_ID вместо %s, \n означает перевод строки. Символ > записывает рабочий файл. Install -d создаёт каталог, следующий install задаёт владельца и права маркера. Хеш проверяет совпадение содержимого.

**Ожидаемый результат и его смысл:**

Три строки с конечным переводом строки, права 0755/0644. Запишите hash. Права 777 не подходят.

**Если не получилось:**

Не оставляйте YOUR-LAB-ID. Используйте анонимный Lab ID, не имя EC2 и не email.

### P3.3 Сохранить доказательство до остановки

**Место выполнения:**

Браузер на своём PC: Web Portal

**Цель и действия:**

Выйдите из Web через exit в CloudShell. В Web Portal выберите P3 и сохраните состояние до остановки. Сохраняются instance/volume/hash marker/boot_id; EC2 ещё не останавливается. Дождитесь успешного сохранения. Все этапы доказательства P3 выполняйте этим браузерным способом.

**Смысл команд и настроек:**

Запись до остановки сохраняет узел, загрузку и marker для сравнения. Кнопка сама не останавливает EC2. Затем выполните AWS Stop; не смешивайте браузерные и командные доказательства.

**Ожидаемый результат и его смысл:**

Состояние до остановки сохранено. После этого marker не редактируйте.

**Если не получилось:**

Остановка после неуспешной подготовки не даст полной цепочки доказательств. Сначала исправьте файл/права/SSM.

### P3.4 Остановить тот же Web и зафиксировать stopped

**Место выполнения:**

AWS Console своего студенческого аккаунта

**Цель и действия:**

Сверьте instance ID своего Web в EC2. Выберите Instance state → Stop instance и дождитесь stopped. Не Reboot/Terminate. Не запуская Web, подтвердите остановку в P3 Web Portal. Остальные четыре сервера не останавливайте.

**Смысл команд и настроек:**

В Console выполните Stop нужного Web; состояние stopped зафиксируйте в Web Portal. Разрыв SSM сам по себе не доказывает остановку. Stop отличается от reboot и Terminate.

**Ожидаемый результат и его смысл:**

Записано stopped того же instance. Во время остановки недоступность HTTP/SSM ожидаема.

**Если не получилось:**

При stopping подождите. Если запустили раньше наблюдения, цепочку из трёх этапов потребуется повторить.

### P3.5 Запустить, сравнить данные и отправить

**Место выполнения:**

AWS Console своего студенческого аккаунта

**Цель и действия:**

Запустите тот же Web и дождитесь running/SSM Online. Через SSM сравните текст/hash и boot_id: instance/volume/hash сохраняются, boot_id меняется. В P3 Web Portal проверьте сохранение после запуска и дождитесь результата и сохранения.

**Смысл команд и настроек:**

Запустите тот же Web и дождитесь running/SSM Online. Checker сравнивает текущее состояние с сохранённым исходным; не пересоздавайте маркер после запуска. Для внешнего доступа далее используйте новый public IP Web.

**Ожидаемый результат и его смысл:**

Три учебные проверки PASS. Если public IPv4 изменился, используйте новый адрес для внешнего HTTP.

**Если не получилось:**

Новый instance не доказывает сохранение. Для P3/M3 нужны отдельные marker и доказательства.

## Проверка понимания (без баллов)

Достаточно ли одинакового текста на новом Web для выполнения задания?

**Объяснение:**

Нет: нужны исходные instance и volume, а также наблюдение остановленного состояния.
