# WEB-00 完成像と通信要件

## 何を作るか

AWSのVPC内にEC2上の踏み台・DNS・Web・DBを構成します。踏み台は公開サブネット、DNS・Web・DBはプライベートサブネットに置きます。学生PCからRDPで踏み台へ入り、踏み台上のブラウザでWebへIP指定、その後web.lab.testの名前指定でアクセスします。Web側に教員提供の小さなアプリを置き、DBの架空データを利用します。学生はアプリのコードを開発せず、サーバー、接続、権限、観測、復旧を担当します。

WEB-02の静的Web演習は、HTTPとWebサーバーを学ぶ途中段階です。最終構成では教員提供アプリを通してWebとDBが接続されます。

## 通信の順序

| 用途 | 送信元 | 宛先 | 観測すること |
| --- | --- | --- | --- |
| リモートデスクトップ | 学生PC | EC2踏み台 | RDP3389、許可接続元 |
| サーバー管理 | EC2踏み台 | DNS・Web・DB | SSH22、SG-Bastion以外を拒否 |
| 名前解決 | EC2踏み台 | EC2上のDNS | 問い合わせ先、WebのIP回答 |
| ページ取得 | 踏み台上のブラウザ | EC2上のWeb・教員提供アプリ | HTTPの応答、Webのlog |
| データ取得 | Web側の教員提供アプリ | EC2上のDB | DB接続、権限、問い合わせの結果 |

Security Groupは必要な通信だけを許可します。実際のEC2台数、IP、portの開放範囲、アプリの起動方式は、AWS Academy Learner Labを学生権限で検証してから手順へ固定します。学生PCからVPC内のDNSやWebへ直接到達できるとは仮定しません。

## 学生が説明すること

1. DNS、Web、アプリ、DBの役割。
2. 名前解決からページ表示、DB応答までの通信の順序。
3. アプリがDBへ接続する理由と、必要な接続元・権限。
4. どの通信を許可し、どの通信を拒否するか。
5. 表示できないときに、DNS、経路、Web、アプリ、DB、logのどこを確認するか。
